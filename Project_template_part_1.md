
# Задание 1. Анализ и планирование


### 1. Описание функциональности монолитного приложения

**Управление отоплением:**

- Пользователи могут удалённо включать/выключать отопление в своих домах.
- Система поддерживает 100 модулей управления отоплением
- К системе подключено 100 клиентских веб-приложений
- Каждая установка сопровождается выездом специалиста по подключению системы отопления в доме
- Самостоятельно подключить свой датчик к системе пользователь не может.
- Система входит в состав монолита на Java с PostgreSQL в качестве СУБД
- Взаимодействие: Синхронное, запросы обрабатываются последовательно

**Мониторинг температуры:**

- Пользователи могут просматривать текущую температуру в своих домах через веб-интерфейс 
- Система получает данные о температуре с датчиков, установленных в домах
- К системе подключено 100 датчиков отопления
- Данные о температуре получаются через запрос от сервера к датчику
- Взаимодействие: Синхронное, запросы обрабатываются последовательно.

### 2. Анализ архитектуры монолитного приложения

Язык программирования: Java
База данных: PostgreSQL
Архитектура: Монолитная, все компоненты системы (обработка запросов, бизнес-логика, работа с данными) находятся в рамках одного приложения.
Взаимодействие: Синхронное, запросы обрабатываются последовательно. Всё управление идёт от сервера к датчику. Данные о температуре также получаются через запрос от сервера к датчику.
Масштабируемость: Ограничена, так как монолит сложно масштабировать по частям.
Развёртывание: Требует остановки всего приложения.

### 3. Определение доменов и границы контекстов

Домен: Упаравление пользователями
- контекст: личный кабинет пользователя, управление
  - сущности: пользователь, дом, подключенные устройства
  - объекты-значения: адрес, email, др. 
  - агрегаты: данные пользователя
  - репозиторий: репозиторий пользователей
  - сервисы: регистрация, изменение данных, добавление/удаление устройств

Домен: Упаравление устройствами
- контекст: включение/выключение устройств
  - сущности: устройства (система отопления, свет, ворота и др), сенсоры
  - объекты-значения: статус устройства (вкл/выкл)
  - агрегаты: устройства
  - репозиторий: репозиторий устройств
  - сервисы: управление устройствами

Домен: Мониторинг и аналитика
- контектст: получение данных от устройств и сенсоров
  - сущности: сенсоры
  - объекты-значения: температура, статус устройства др.
  - агрегаты: параметры
  - репозиторий: репозиторий устройств
  - сервисы: получение данных с устройств, аналитика

Домен: Видеохостинг
- контектст: получение и обработка данных с видеокамер
  - сущности: видеокамеры
  - объекты-значения: видеострим
  - агрегаты: видеопоток
  - репозиторий: видеохостинг
  - сервисы: сохранение и обработка видеопотока, управление видеокамерами

### **4. Проблемы монолитного решения**

Состояние компании в настоящий момент не позволяет в полной мере реализовать новые бизнес-цели. Для этого требуется пересмотр и оптимизация всей экосистемы.

Проблемы развития текущего решения:
- Длительный цикл разработки и развертывания нового функционала - есть риск, что Компания не успеет выполнить условия тендера к назначенным срокам. Компании нужно ускорить разработку новых функций
- Трудно масштабировать отдельные компоненты системы (модуль управления устройствами, модуль мониторинга)
- Высокий риск ошибок - изменения в одной части приложения могут непредсказуемо влиять на другие части
- Синхронное взаимодействие сервисов - могут возникнуть проблемы при росте пользовательской базы
- Развёртывание: Требует остановки всего приложения
